# 운영 개선과 현장 지원

시험·교육 서비스의 오류 분석, 관리 화면 수정, 데이터 처리 개선과 현장 지원 업무에 참여하였습니다.

## Coverlook 운영 요청 등록 화면

운영 요청 등록 화면의 개선에 참여하였습니다. 회사·담당자·프로젝트 선택 항목과 요청 내용을 한 화면에서 처리하였습니다. 회사 조건으로 담당자와 프로젝트 목록을 조회하고 선택 항목에 연결하였습니다.

코드 예제는 회사 식별자를 두 조회 함수에 전달하고 담당자·프로젝트 선택 목록을 반환합니다. 담당자가 없으면 선택값을 비우고 조회 오류는 호출자에게 전달합니다. JSP·Vue·jQuery 화면의 데이터 흐름을 별도 함수로 구성한 예제입니다.

| 입력 | 처리 결과 |
|---|---|
| 회사 A 선택 | A의 담당자·프로젝트 목록 조회 |
| 담당자 목록 존재 | 첫 담당자를 선택값으로 사용 |
| 담당자 목록 없음 | 선택값 없음 |
| 조회 실패 | 오류 반환 |

[코드](../samples/maintenance-ui/companySelection.mjs) · [테스트](../samples/maintenance-ui/companySelection.test.mjs)

빈 목록 처리와 반환 필드 제한은 예제에 적용한 규칙입니다. 파일 업로드·화면 렌더링·연속 요청의 응답 순서 제어는 포함하지 않습니다.

## 서버 설치와 Linux 점검

현장 서버 설치와 Linux 운영환경 점검에 참여하였습니다. 계정, 파일 권한, 실행 서비스, 패치와 로그를 항목별로 점검하고 조치 결과를 문서화하였습니다. 운영 영향이 있는 설정은 필요한 접속 조건과 서비스 사용 여부를 정리하여 협의하였습니다.

| 업무 | 수행 내용 |
|---|---|
| 서버 설치 지원 | 현장 서버 설치와 서비스 실행환경 구성 지원 |
| 계정·권한 점검 | 계정, 파일 소유자와 접근 권한 확인 |
| 서비스·패치 점검 | 사용 서비스 확인과 시스템 최신화 작업 |
| 로그 확인 | 로그인·실패 접속·권한 사용 기록의 조회 방법 정리 |
| 작업 문서화 | 조치 결과와 협의가 필요한 사항 정리 |

## 오류 분석과 성능 확인

서비스 오류 발생 시 요청 데이터, 애플리케이션 로그, Service 처리와 Mapper·SQL을 순서대로 확인하였습니다. 화면과 DB 데이터가 다른 경우 조회 조건과 저장 경로를 확인하여 수정하였습니다.

부하 시험에서는 JMeter로 요청 시나리오를 실행하고 Scouter에서 응답시간·CPU·메모리·SQL 시간을 확인하였습니다. 정적 리소스, HTTP 압축, 스레드 수와 로그 설정을 바꾸어 결과를 비교하였습니다.
