# 운영 개선과 현장 지원

여러 시험·교육 서비스의 운영 기능 개선, 오류 분석, 화면 수정과 현장 지원에 참여하였습니다. 아래에는 기존 프로젝트 저장소에 포함되지 않았던 운영 업무를 정리하였습니다.

## Coverlook 운영 요청 등록 화면

운영 요청 등록 화면의 개선에 참여하였습니다. 회사·담당자·프로젝트 선택 항목과 요청 내용을 한 화면에서 다루고, 회사 조건으로 담당자와 프로젝트 목록을 조회해 선택 항목에 연결하는 흐름입니다.

요청 등록 JSP에는 본인 SVN 수정 정보가 남아 있습니다. 연결된 JavaScript의 목록 조회 흐름도 확인하였으나 해당 JavaScript 전체의 본인 변경 이력은 확보하지 못하였습니다. 화면 개선 담당과 연결 구조를 설명하는 범위로 작성하였습니다.

공개 예제는 회사 식별자를 두 조회 함수에 전달하고 담당자·프로젝트 선택 목록을 만드는 함수로 재작성하였습니다. UI 데이터에는 가상의 식별자와 표시 이름만 사용하였습니다.

- 예시: 회사 A 선택 → A의 담당자·프로젝트 목록 조회 → 첫 담당자 선택 → 프로젝트 선택 대기.
- 빈 목록 예시: 담당자가 없는 회사 → 선택값 없음으로 처리.
- 검증: 두 조회에 같은 회사 조건 전달, 표시 필드 구성, 빈 목록, 조회 오류 전달을 확인하였습니다.
- [구현](../samples/maintenance-ui/companySelection.mjs) · [테스트](../samples/maintenance-ui/companySelection.test.mjs)

원본은 JSP·Vue·jQuery를 함께 사용합니다. 공개 예제는 비동기 순수 처리 함수로 분리하였고, 빈 목록 처리와 반환 필드 제한을 보완하였습니다. 연속 클릭 시 이전 응답이 화면을 덮어쓰는 문제까지 해결한 예제는 아닙니다. 실제 화면 렌더링·파일 업로드·개인 연락처 처리는 재현하지 않았습니다.

## 시험 서비스의 서버 설치·보안 점검 지원

현장 서버 설치와 Linux 운영환경 점검 업무에 참여하였습니다. 계정, 파일 권한, 서비스, 패치와 로그 항목을 나누어 점검 내용을 정리하고, 조치 여부와 운영 협의가 필요한 사항을 구분하였습니다. 보관된 작업 보고서에는 시스템 최신화 완료 기록과 항목별 검토 내용이 남아 있습니다.

실제 기관의 보안 설정, 미조치 항목, 서버 주소와 점검 결과 원문은 공개하지 않았습니다. 아래는 진행 방식을 설명하기 위한 가상의 업무 기록입니다.

| 설명용 항목 | 진행 방법 | 남길 결과 |
|---|---|---|
| 패키지 정비 | 변경 대상과 서비스 영향을 확인하고 업데이트 후 실행 상태를 점검 | 변경 내용·확인 결과 |
| 접근 정책 변경 | 운영에 필요한 접속 조건을 정리하고 변경 범위를 협의 | 협의 대상·결정 사항 |
| 비사용 서비스 확인 | 설치·실행 여부를 확인하여 적용 대상 여부 판단 | 확인 근거·비대상 사유 |
| 로그 검토 | 로그인·실패 접속·권한 사용 기록의 조회 방법 정리 | 조회 범위·후속 확인 사항 |

표의 상세 진행 단계는 공개 설명을 위해 재구성하였습니다. 자동 점검 도구 개발, 모든 취약점 조치 완료, 정기 점검 운영 정착으로 확대하여 설명하지 않았습니다. 현장 기관명과 보관 문서의 기관명 대응 관계가 확정되지 않아 이 사례는 공통 운영 업무로 정리하였습니다.

## 오류 분석·성능 확인·배포 대응

시험·운영 기능의 오류를 재현하고 화면 입력, Service 처리, 조회 조건과 로그를 확인하여 수정 범위를 정리하였습니다. 성능 확인은 요청 시나리오와 서버 자원·SQL 관측 결과를 함께 보는 방식으로 수행하였습니다. 정량 결과가 남은 사례는 [ClassRoom 부하 시험](https://github.com/jeon97/iosys_online_test_platform/blob/main/docs/PERFORMANCE-TEST.md)으로 연결하였습니다.

특정 SQL의 실행계획 전후 비교나 장애 감소 수치가 확인되지 않은 업무에는 성능 개선율을 기재하지 않았습니다. GitHub의 공개 예제 테스트 수를 실제 운영 장애 감소나 회사 시스템 전체의 품질 지표로 사용하지 않았습니다.

## 예제 실행

```sh
node --test samples/maintenance-ui/companySelection.test.mjs
```

기존 6개 상세 저장소는 유지하고, 이 저장소에는 별도 상세 저장소가 없는 공통 업무의 설명과 작은 화면 데이터 예제만 두었습니다.
