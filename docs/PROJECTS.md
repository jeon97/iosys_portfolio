# 프로젝트별 상세

## 실시간 온라인 평가 운영 플랫폼

여러 마이크로서비스가 시험 문맥과 데이터를 일관되게 다루도록 공통 모델과 저장소 경계를 구성했습니다. 응시자 답안·상태·접속·채팅·카메라 API, JWT와 Redis 기반 인증, Gateway 필터, RabbitMQ 이벤트 워커와 관리자 데이터 반입 기능을 담당했습니다.

- 핵심 판단: 현재 상태와 영속 이력의 저장 책임 분리
- 장애 대응: 큐 발행 실패 시 대체 저장 경로 확보
- 운영 검증: JMeter 시나리오와 Scouter 관찰 항목 정리
- [상세 저장소](https://github.com/jeon97/iosys_realtime_assessment_platform)

## 온라인 시험 및 문항 관리 플랫폼

시험 데이터 사전점검부터 시험장·좌석 배정, 응시, 결과와 부정행위 통계까지 운영 기능을 개발했습니다. 문항 관리 영역에서는 검토계획 구성, 선정위원 자동·수동·엑셀 배정과 문항 통계를 담당했습니다.

- 핵심 판단: 시험 시작 전 필수 데이터와 배정 중복 검증
- 데이터 처리: 목록·통계·엑셀에 같은 조회 기준 적용
- 외부 연계: 개발 당시 약 30개 API를 다뤘으며, 보관된 명세로 23개 계약을 확인해 공개 문서에 구분 표기
- [상세 저장소](https://github.com/jeon97/iosys_online_test_platform)

## 자격시험 통합 운영 시스템

CBT 시험실의 응시 상태와 좌석을 모니터링하고 시간 연장·재시작·채점 확정 기능을 개발했습니다. 통합 운영 영역에서는 시행결과와 합격 데이터 처리, 전문가 인력풀과 설문을 담당했고 문항 시스템의 출제계획과 선정 기능을 구현했습니다.

- 핵심 판단: 확정과 확정 취소의 데이터 정합성 유지
- 대량 처리: 접수자·결과 목록을 구간으로 나눠 처리
- 외부 연계: 전송 완료 키와 실패 이력을 기준으로 안전하게 재실행
- [상세 저장소](https://github.com/jeon97/iosys_certification_test_system)

## 교육사업 통합 운영 시스템

참여자의 모집·신청과 운영기관의 사업계획, 예산 변경, 보조금 반환, 정산, 워크숍과 안내 업무를 개발했습니다. 신청자 화면과 관리자 화면을 함께 다뤄 업무 흐름 전체를 연결했습니다.

- 핵심 판단: 신청 정원과 시험실 수용 인원을 저장 직전에 재확인
- 변경 관리: 예산과 정산 상태 전이 및 이력 보존
- 운영 지원: 대량 안내의 성공·실패 분리와 증명서 발급 이력
- [상세 저장소](https://github.com/jeon97/iosys_education_business_operations_system)

## 대학 글쓰기 지원 플랫폼

기관별 로그인과 SSO, 중복 세션, 사용자 권한과 접근 조건을 처리했습니다. 관리자가 접속·활동 로그를 검색하고 내려받거나 보존기간이 지난 로그를 삭제하는 기능, 게시판 편집과 학사 사용자·강좌 검색도 개발했습니다.

- 핵심 판단: 외부 인증과 내부 세션 정책의 책임 분리
- 보안: 허용된 이동 경로와 관리자 접근 조건 확인
- 데이터 연계: 운영 DB와 분리된 학사정보 조회용 View 설계
- [상세 저장소](https://github.com/jeon97/iosys_writing_center)

## 범용 sLLM JSON API

업무 화면마다 달랐던 로컬 LLM 호출 방식을 하나의 FastAPI로 통합했습니다. 입력 정제, 모델 허용 목록, JSON 스키마 검증, 제한된 재시도와 원문을 남기지 않는 감사 로그를 구현했습니다.

- 핵심 판단: 업무 프롬프트와 공통 모델 호출 책임 분리
- 평가: 200건의 수작업 기준과 네 가지 프롬프트 결과 비교
- 재실행: 레코드별 체크포인트와 실패 격리
- [상세 저장소](https://github.com/jeon97/iosys_ai_api)
